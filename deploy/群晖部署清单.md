## 2. 生成凭据（务必重新生成，不要复用测试值）

开发期用的是临时测试口令与临时 secret，**切勿复用，也不要写进任何文档、示例或提交**。生产必须重新生成（下面两条命令的输出只填进 `deploy/.env`，`.env` 已被 `.gitignore` 排除）：

```bash
openssl rand -base64 32     # NEXTAUTH_SECRET，至少 32 位
openssl rand -base64 24     # HOMEPAGE_AUTH_PASSWORD
```

```bash
cd deploy
cp .env.example .env
# 编辑 .env，填入上面生成的两个值、NEXTAUTH_URL、HOMEPAGE_ALLOWED_HOSTS
```

四个必需变量（compose 中已声明）：

| 变量 | 说明 |
|---|---|
| `HOMEPAGE_AUTH_ENABLED` | 固定 `true` |
| `HOMEPAGE_AUTH_PASSWORD` | 登录密码（内置鉴权只认密码，无用户名字段） |
| `NEXTAUTH_SECRET` | ≥32 位随机值 |
| `NEXTAUTH_URL` | 实际访问地址，如 `http://群晖IP:3000` 或 `https://你的域名` |

`HOMEPAGE_ALLOWED_HOSTS` 建议**同时写域名和内网 IP**（逗号分隔），例如 `home.example.com,192.168.1.100:3000`（此处仅为示例 IP，请换成你自己的）；`NEXTAUTH_URL` 的 host 会被自动信任，但用 IP 直接访问时仍需列出来，否则会被 `400 Host validation failed` 拦截。

## 3. 配置目录权限（写回功能的关键）

容器内以 **UID 1000** 运行，`HOMEPAGE_CONFIG_DIR=/app/config` 必须**可写**，否则管理页保存会 500：

```bash
# 群晖 SSH 中执行，路径按实际共享文件夹调整
sudo mkdir -p /volume1/docker/homepage/config
sudo chown -R 1000:1000 /volume1/docker/homepage/config
sudo chmod -R u+rwX /volume1/docker/homepage/config
```

把脱敏后的配置文件复制进该目录。`bookmarks.yaml` 写回前会自动生成 `bookmarks.yaml.时间戳.bak`（保留最近 10 份），这些 `.bak` 同样含配置内容，注意别外传。

## 4. 构建与启动

```bash
cd deploy
docker compose up -d --build
docker compose logs -f homepage
```

官方 Dockerfile 是多阶段构建，首次构建约数分钟。`deploy/.env` 已被 `.gitignore` 排除。

> **构建期 / 运行期 env 一致性**：`proxy.js` 与 `withAuth` 已在请求时求值，正常不会出问题；
> 但 `[...nextauth].js` 仍在模块加载时读取 `HOMEPAGE_AUTH_ENABLED`。若日志出现
> "auth is enabled at runtime but was disabled when the server bundle was built"，
> 说明镜像是在未开启鉴权时构建的，请保持 `.env` 不变重新 `--build`。

## 7. 安全提醒

- 公开读白名单可通过 `HOMEPAGE_PUBLIC_READ_PATHS` 扩展，但**不要**把 `/api/config/bookmarks`、`/api/services/proxy`、`/api/revalidate`、`/api/mcp` 加进去。
- 以后若在 `services.yaml` 里加 Docker / NAS / K8s 组件，注意 `/api/services/proxy` 默认受保护；若为了展示效果放开它，等于允许匿名转发到内网服务，请自行评估。
- 壁纸图源当前为第三方镜像站，会向第三方暴露访客 IP/访问时间；如介意，改为自托管图片或纯 CSS 背景。
- `.env`、`*.bak`、备份目录都不要提交到 GitHub 或打进镜像。
